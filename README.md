# tool-pdf-workbench — PDF 작업대

PDF 를 떨어뜨리면 페이지 그리드가 뜨고, 그 자리에서 배치를 바꾸고 무언가를 얹고
원하는 형태로 내보낸다. **모드 전환이 없다.**

## 왜 "툴 목록" 이 아닌가

iLovePDF 는 30개 툴을 6개 카테고리(Organize / Optimize / Convert / Edit / Security)로
나눈다. 이건 **소프트웨어가 파일에 무슨 짓을 하는가**의 분류다. 엔드포인트 하나가
파일 하나를 처리하는 서버 구조에서 나온 형태이고, 사용자에게는 매번 5행동을 물린다.

같은 19개 기능을 **사용자가 묻는 질문**으로 다시 나누면 네 자리로 접힌다.

| 사용자가 묻는 것 | iLovePDF 의 해당 툴 | 여기서의 정체 |
| --- | --- | --- |
| 뭘 가지고 시작하지 | Merge · JPG to PDF · Scan · Unlock · Repair | **입력** |
| 페이지를 어떻게 배치하지 | Organize · Remove · Extract · Rotate | **직접 조작** |
| 위에 뭘 얹지 | Page numbers · Watermark · Sign · Crop · Forms | **덧입히기** |
| 어떤 형태로 받지 | Split · Compress · Protect · PDF/A · to JPG · to Markdown | **내보내기 옵션** |

세 가지가 따라 나온다.

1. **병합·정렬·삭제·회전은 기능이 아니라 손동작이다.** 드래그하면 정렬, `×` 면 삭제,
   파일을 하나 더 떨구면 병합. 고를 대상 자체가 없어진다.
2. **압축·암호·PDF/A·JPG·분할은 기능이 아니라 내보내기 옵션이다.** 그래서 **압축과
   암호를 동시에** 걸 수 있다 — iLovePDF 에서는 두 번 왕복해야 하는 일이다.
3. **암호풀기·복구는 드롭 시점의 자동 대응이다.** 사용자는 자기 파일이 깨졌다는 걸
   모른다. 잠겼으면 비밀번호를 묻고, 깨졌으면 복구를 시도한다.

사용자가 목록에서 골라야 하는 것은 **덧입히기 5개뿐**이다.

## 클릭 예산

| 작업 | 행동 수 | iLovePDF |
| --- | --- | --- |
| 병합 | **2** — 드롭 → 내보내기 | 5 |
| 분할 · 정렬 · 회전 · 압축 · 암호 | **3** — 드롭 → 조작 → 내보내기 | 5 |
| 압축 + 암호 동시 | **3** | 10 |
| 워터마크 · 번호 · 서명 | **5** — 드롭 → 선택 → 입력 → 적용 → 내보내기 | 5 |

묻지 않고 정하는 것:

- 페이지 순서 — 드롭한 파일 순서, 파일 안에서는 원래 페이지 순서
- 출력 파일명 — 첫 입력 파일명 기반. 수정 가능하되 필수 아님
- 출력 형식 — PDF. 나머지는 바꾸고 싶을 때만 건드린다
- 잠긴 파일 — 드롭 시점에 비밀번호를 묻는다. 사용자가 "암호풀기" 를 찾아가지 않는다

## 실패 체크리스트

구현 전에 정의한다. 전부 검증되기 전까지 완료가 아니다 (@failure-checklist-first).

### 정확성

- [ ] 출력 페이지 수 == 작업대에 남은 페이지 수
- [ ] 페이지 순서가 그리드에 보이는 순서와 같다
- [ ] 회전한 페이지가 출력에서도 그 각도다 (90/180/270 누적 포함)
- [ ] 삭제한 페이지가 출력에 없다
- [ ] 텍스트 PDF 를 병합해도 **텍스트가 선택 가능하다** (래스터화되지 않는다)
- [ ] 이미지를 페이지로 넣을 때 원본 바이트를 재인코딩하지 않는다
- [ ] 암호 건 PDF 가 그 비밀번호로 열리고, 틀린 비밀번호로는 안 열린다
- [ ] 압축 후에도 페이지 수·순서·텍스트가 보존된다

### 경계

- [ ] 파일 0개 — 내보내기 버튼이 비활성이고 **왜 비활성인지 한 줄** 보인다
- [ ] 1페이지짜리 PDF 하나 — 분할 옵션이 의미 없음을 알린다
- [ ] 200페이지 / 400MB — 브라우저가 죽지 않는다
- [ ] 페이지 전부 삭제 — 빈 상태로 되돌아가고 크래시하지 않는다

### 오염된 입력

- [ ] 손상 PDF 하나가 나머지 파일 전체를 실패시키지 않는다
- [ ] 잠긴 PDF 를 떨구면 비밀번호를 묻는다. 취소하면 그 파일만 빠진다
- [ ] PDF 가 아닌 파일(.txt, .zip)을 떨구면 무시하고 이유를 알린다
- [ ] 0바이트 파일이 앱을 죽이지 않는다

### 응답성

- [ ] 200페이지 드롭 시 썸네일이 **보이는 것부터** 뜬다 (전부 기다리지 않는다)
- [ ] 썸네일 렌더 중에도 내보내기 패널을 조작할 수 있다
- [ ] 진행률이 "n / m 페이지" 로 보인다. 스피너만 도는 화면을 만들지 않는다
- [ ] 내보내기 중 UI 가 얼지 않는다

### 겹침·잘림 (`skill:ui-probe` 로 잰다, 눈으로 보지 않는다)

- [ ] 셀렉트의 셰브론이 글자를 덮지 않는다 (@control-contract #3)
- [ ] 긴 파일명이 페이지 카드를 밀지 않는다
- [ ] 클릭 대상이 24×24 이상
- [ ] 같은 태그의 컨트롤 변형이 한 화면에 넷 미만

### 재정렬 (@reorder-affordance — 그대로 가져온다)

- [ ] 10개 중 마지막을 첫 자리로 옮길 수 있다
- [ ] 10개 중 첫 항목을 **맨 뒤**로 옮길 수 있다
- [ ] 드래그 중 삽입선이 정확히 하나 보인다
- [ ] 표시된 틈과 놓은 결과가 일치한다
- [ ] 제자리에 놓으면 순서·번호가 변하지 않는다
- [ ] ESC 로 취소하면 순서가 그대로다
- [ ] 키보드만으로 순서를 바꿀 수 있다 (`Alt+←/→`)

### 결과 검수

- [ ] 내보낸 PDF 를 실제로 열어 페이지를 눈으로 확인한다
- [ ] 암호 건 PDF 를 다른 뷰어에서 열어 본다
- [ ] "코드상 맞다" 는 검증이 아니다

## 기능 범위

**넣는 것 (A군 18개)** — 브라우저에서 끝난다 (@client-first-processing).

병합 · 분할 · 페이지삭제 · 페이지추출 · 정렬 · 회전 · 자르기 · JPG→PDF · PDF→JPG ·
페이지번호 · 워터마크 · 서명 · 암호걸기 · 암호풀기 · PDF/A · 복구 · 폼 · 텍스트추출

**안 넣는 것** — 브라우저에서 불가능하거나 서버 키가 필요하다.

| 기능 | 이유 |
| --- | --- |
| Word/PPT/Excel ↔ PDF | LibreOffice wasm 은 100MB+ 에 불안정. 2026 현재 프로덕션 부적합 |
| AI 요약 · 번역 | 서버 키가 필요하다 (@client-first-processing 예외 1) |
| 압축 · OCR | 2차. wasm(qpdf 1.3MB / tesseract kor 15MB)이 추가로 붙는다 |
